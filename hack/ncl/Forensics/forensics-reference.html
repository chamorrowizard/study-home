MEMORY HARD

> Memory Dump Triage & OS Extraction

Identify operating system architecture, environmental variables, and active sessions from raw live system memory dumps (.mem, .raw, .vmem) using Volatility3.

// When to Use This

  • Initial triage stage of a host memory dump during incident response or CTF forensic challenges.
  • When establishing target hostname, active users, system architecture, or timezones before deeper artifact scanning.

// Why This Specific Approach Works

Volatility3 parses kernel structures dynamically using symbol tables without legacy profile definitions. Extracting environmental variables (envars) reveals per-process environment blocks where critical details like COMPUTERNAME, user profiles, and active working paths reside.

// Key Commands

./vol.py -f ./memdump.mem windows.info.Info
./vol.py -f ./memdump.mem windows.envars.Envars | grep -i "COMPUTERNAME\|USERNAME"
! Gotcha / Version Note Specific Volatility3 commits may parse symbol tables differently. If plugin execution fails, check Python dependencies or specify exact virtual environments with pycryptodome installed.

MEMORY HARD

> Memory File Scan & Virtual Address Dumping

Locate active file handles in system RAM, map target paths, and dump cached file objects (databases, documents, logs) directly to disk using virtual memory addresses.

// When to Use This

  • When searching for documents, browser history databases (SQLite), or open file handles present in memory at the time of system capture.
  • When the target file is deleted from physical storage but remains cached in Windows memory management pages.

// Why This Specific Approach Works

windows.filescan inspects FILE_OBJECT headers across kernel memory pools. Passing the specific virtual memory address (--virtaddr) to DumpFiles allows reconstruction of cached page streams directly to local output directories.

// Key Commands

./vol.py -f ./memdump.mem windows.filescan.FileScan | grep -i "Users"
./vol.py -f ./memdump.mem -o ./out windows.dumpfiles.DumpFiles --virtaddr 0xe00012345678
! Encoding Trap Non-English filenames or special path characters may output garbled text in standard terminals. Pipe commands through iconv or inspect UTF-8 streams when searching directory strings.
// Documentation Links [SQLite DB Browser]
ARTIFACTS MEDIUM

> NTLM Hash Dumping & Registry Analysis

Extract NTLM password hashes from local Security Account Manager (SAM) and SYSTEM registry hives stored in system memory.

// When to Use This

  • When recovering user account credentials or verifying local password complexity enforcement from host memory.
  • To obtain NTLM hashes for offline cracking via Hashcat, John the Ripper, or online lookup databases.

// Why This Specific Approach Works

The Windows kernel maps hive structures into RAM. Volatility locates registry hive base addresses in memory, locates LSA secrets and SAM structures, and decrypts stored user password hashes without locking hive files.

// Key Commands

./vol.py -f ./memdump.mem windows.registry.hashdump.Hashdump
hashcat -m 1000 -a 0 ntlm_hashes.txt /usr/share/wordlists/rockyou.txt
! Crypto Dependency Error If Volatility throws a cryptographic plugin failure, missing libraries are typically the cause. Resolve by running pip3 install pycryptodome inside your python environment.

FILE_SYSTEM MEDIUM

> File Carving & Magic Byte Repair

Extract raw binary payloads, repair corrupted header signatures (Magic Bytes), and recover deleted files using tools like scalpel, foremost, and hex editors.

// When to Use This

  • When file system metadata (MFT/FAT) is unreadable, corrupted, or wiped.
  • When an image, zip, or executable fails to render due to intentional header byte tampering in CTF challenges.

// Why This Specific Approach Works

Carving scans raw disk sectors for explicit header/footer byte sequences (e.g., PNG = 89 50 4E 47 0D 0A 1A 0A). Overwriting broken headers with correct hex signatures restores standard container rendering across operating systems.

// Key Commands

foremost -t png,jpg,pdf,zip -i disk_image.raw -o ./recovered_output
hexeditor broken_file.png # Verify magic bytes match 89 50 4E 47
! Fragmentation Trap File carving tools assume contiguously allocated sectors. Heavily fragmented disk images may produce corrupt outputs; verify boundaries manually in a hex editor if carving fails.
// Documentation Links [Foremost Manual]
GIT EASY

> Git Repository Forensics & Commit Recovery

Extract deleted secrets, inspect dangling commit blobs, and review commit logs inside compromised or improperly scrubbed .git version control directories.

// When to Use This

  • When analyzing source code repositories where credentials, flags, or private keys were committed and later removed via git rm.
  • When inspecting exposed .git directories harvested from target web servers.

// Why This Specific Approach Works

Git stores objects immutably inside .git/objects by SHA-1 hash. Removing a file or force-pushing does not immediately delete dangling blobs until garbage collection (git gc) runs, leaving unreferenced data fully recoverable via git fsck.

// Key Commands

git log --all --full-history -- "path/to/file"
git fsck --lost-found | grep "dangling blob" | awk '{print $3}' | xargs -I {} git cat-file -p {}
! Hidden Stash Gotcha Always run git stash list and inspect git reflog. Secrets are frequently left behind in uncommitted stash states during developer workflows.
// Documentation Links [Git FSCK Reference]
