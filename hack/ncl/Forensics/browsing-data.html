Concept 01

Browser History as a Digital Diary

Imagine every time you walk into a library or a store, an invisible helper automatically writes down the exact second you arrived, the exact book or shelf you looked at, and what you typed into the search kiosk.

The Forensics Translation:

Browsers like Firefox and Chrome record every webpage visit inside local SQLite database files (`places.sqlite`). Even if you close the browser tabs, this "diary" remains on your computer's hard drive until overwritten or wiped.

Concept 02

SQLite Databases as Structured Filing Cabinets

Think of standard text files like loose notes scattered across a desk. Finding a specific fact takes forever. An SQLite database is like a heavy, indestructible metal filing cabinet with neatly labeled drawers (tables), folders (rows), and index cards (columns).

The Forensics Translation:

Instead of manually reading thousands of lines of text, investigators use Structured Query Language (SQL) to ask the cabinet precise questions: "Show me every URL visited between 2:00 PM and 3:00 PM!"

Deep Dive

Core Concepts & Technical Definitions

Essential terminology every cybersecurity analyst must know when analyzing browser artifacts.

Database

moz_places & moz_historyvisits

Firefox's core history storage tables. moz_places stores unique URLs, page titles, and visit counts. moz_historyvisits logs every individual click or page load event with microsecond-precision timestamps.

Why it matters: Allows correlating unique web pages with exact temporal timelines.
Timekeeping

Microsecond Epoch Timestamps

Unlike standard Unix timestamps (seconds since Jan 1, 1970), Firefox history often records timestamps in microseconds (millionths of a second) or 13-digit milliseconds.

Why it matters: Requires division by 1,000,000 before converting via datetime() in SQLite.
Networking

Base Domains vs. Subdomains

A subdomain (support.mozilla.org) points to a specific section, while the base domain (mozilla.org) represents the root organizational domain.

Why it matters: Analysts deduplicate subdomains to evaluate unique external organizations visited.

Practical Investigation

Forensic Workflow & Attacker Objectives

What security analysts look for when investigating compromised or suspicious endpoints.

01

Inspecting Database Schema

Phase 1: Reconnaissance

Before querying data, an analyst must understand how tables relate to one another. Using the sqlite3 command-line interface, inspect table definitions to locate timestamp columns and foreign keys.

player@intern:~$ sqlite3 places.sqlite ".schema moz_historyvisits"
02

Calculating Session Duration & Timelines

Phase 2: Temporal Analysis

To find how long an activity window lasted, subtract the earliest visit timestamp from the latest visit timestamp, then convert microsecond differences into minutes.

player@intern:~$ sqlite3 places.sqlite "SELECT MIN(visit_date), MAX(visit_date), (MAX(visit_date) - MIN(visit_date)) / 1000000 / 60 AS minutes_elapsed FROM moz_historyvisits;"
03

Extracting Search Queries & Intent

Phase 3: Intent Extraction

Search engines encode user intent in URL parameters (e.g., q=...). Sorting history by database ID in descending order reveals the user's final search queries before session closure.

player@intern:~$ sqlite3 places.sqlite "SELECT url FROM moz_places WHERE url LIKE '%q=%' ORDER BY id DESC LIMIT 3;"

Command & Tool Cheat Sheet

Handy utilities and SQL statements for rapid browser forensics investigation.

Utility / Command Purpose & Description Practical Example
sqlite3 filename.sqlite Opens an interactive SQLite shell session for querying local database files. sqlite3 places.sqlite
.schema [table_name] Displays SQL CREATE statements showing table columns and data types. .schema moz_places
SELECT ... LIKE '%term%' Filters database records containing specific keywords or search parameters. SELECT url FROM moz_places WHERE url LIKE '%benchmark%';
datetime(col/1000000, 'unixepoch') Converts raw microsecond epoch integers into readable UTC calendar dates. SELECT datetime(visit_date/1000000, 'unixepoch') FROM moz_historyvisits;
