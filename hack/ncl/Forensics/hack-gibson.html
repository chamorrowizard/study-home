Mainframes & Enterprise Systems

Understanding heavy-duty enterprise computing & IBM's legacy

What is a Mainframe? Imagine a regular home PC or laptop is like a delivery motorcycle—great for personal errands, quick tasks, and everyday browsing. A mainframe, on the other hand, is like a massive, indestructible freight train designed to haul thousands of tons of cargo nonstop across the country without ever breaking down. Mainframes are hyper-powerful computers designed to process billions of transactions every single day.

Why Financial Institutions & Governments Use Them: Banks, credit bureaus, insurance companies, and tax agencies handle massive databases containing gigabytes or terabytes of vital records. When you swipe your debit card or transfer funds, that change must reflect instantly and with 100% accuracy. Mainframes excel at doing this concurrently for millions of users without crashing.

IBM's Role: IBM pioneered commercial mainframe manufacturing in the 1950s. Back then, competitors were nicknamed "IBM and the Seven Dwarfs." Today, IBM remains the undisputed giant in this space, constantly modernizing mainframes—even adding integrated on-chip AI accelerators in recent models to handle modern workloads.

Key Concept: Reliability & MTBF

Mainframes are built with complete hardware redundancy—meaning backup parts are built right inside the machine. Their reliability is measured in MTBF (Mean Time Before Failure), which on mainframes is measured in decades rather than years.

Python Virtual Environments

Isolating dependencies and managing project folders safely

Explain Like I'm Five: Imagine working on an art project at a shared community table where everyone uses the same jar of paint. If Project A needs bright neon pink paint, but Project B needs dark pastel pink, mixing them globally ruins everything. A virtual environment is like giving each project its own private, self-contained art box with its exact tools and colors inside.

Virtual Environment vs. Virtual Machine: Beginners often confuse these. A Virtual Machine (VM) is like running an entire simulated computer inside your computer (complete with its own operating system). A Virtual Environment is much lighter—it's simply a designated folder (`.venv`) that tells Python: "Look for libraries only inside this folder, not across the whole operating system."

Why Developers Use Them: Different software projects rely on different versions of libraries. Isolating dependencies prevents version conflicts (e.g., Project 1 needing Python 2 libraries while Project 2 runs Python 3).

What's Inside a Virtual Environment?

  • Bin / Scripts Folder: Contains executable scripts and activation files.
  • Lib / Site-Packages: Where local package dependencies installed via `pip` live.
  • Configuration Files: The essential configuration files that tell Python to restrict library searches strictly to this directory.
  • Hidden Prefix (`.venv`): Starting a folder name with a dot (`.`) hides it by default in Linux/Mac directory listings.

Software Bills of Materials (SBOMs)

Inventorying software components for rapid vulnerability patching

What is an SBOM? Think of an SBOM like the ingredient label on the back of a cereal box or food package. Instead of listing grains and vitamins, an SBOM lists every single software library, third-party component, and dependency baked into an application.

Why They Matter in Cybersecurity: When a massive zero-day vulnerability strikes (such as the famous Log4j security incident), Chief Information Security Officers (CISOs) immediately need to know: "Do any of our apps use this vulnerable component?" Without an SBOM, teams are flying blind. With an SBOM, they can pinpoint vulnerable software instantly and patch it within minutes.

Character Encodings: ASCII vs. EBCDIC

Decoding mainframe text formats and recognizing hex patterns

What is Character Encoding? Computers only understand numbers (0s and 1s). An encoding is a translation dictionary that maps numbers to letters and symbols.

ASCII vs. EBCDIC: Most modern computers use ASCII. However, legacy IBM mainframes use EBCDIC (Extended Binary Coded Decimal Interchange Code), an older encoding standard developed in the 1960s.

Spotting EBCDIC in a Hex Dump: When an analyst opens an EBCDIC-encoded database file in a hex editor, they notice repeating hex values like 40 40 40 everywhere. In EBCDIC, `40` represents a space! Recognizing this pattern is the crucial "aha moment" that reveals the file needs a translation tool (like `dd`) to convert into readable ASCII.

Password Hashing & Cracking Basics

Understanding RACF hashes, wordlists, and John the Ripper

What is a Password Hash? A hash is a one-way mathematical scrambler. Instead of storing your actual password (e.g., `Secret123`), systems store a scrambled cryptographic hash (e.g., `5e88489...`). When you log in, your password is hashed and compared against the stored hash.

RACF Hashes & z/OS: Mainframe systems (running IBM's z/OS operating system) manage user security credentials using RACF (Resource Access Control Facility) hashes.

Password Cracking Tools: Security professionals use tools like John the Ripper combined with massive common password wordlists (like RockYou) and modification rules (such as `best64` rules that test common leetspeak substitutions) to test password strength and audit system security.

What the Attacker Wanted & Step-by-Step Forensics

Analyzing a mainframe compromise and executing the recovery steps from scratch

Target Objectives: What Was the Attacker Looking For?

In this scenario (Nor Central Loans mainframe compromised by the group Liberation), an attacker breaks into a high-value corporate or financial mainframe. They aren't just looking to vandalize; they are performing data exfiltration and reconnaissance. Specifically, they target:

  • Database Archives & Backup Dumps (.xmi / Net Data): Bundled database tables containing sensitive records, communications, and system configurations.
  • User Credential Tables: Account names and user authorization stores.
  • Password Hashes (RACF): Encrypted user credentials that can be cracked offline to escalate privileges and access deeper systems.

Complete Step-by-Step Forensics & Cracking Walkthrough

Step 1: File Inspection & Initial Analysis

Download the evidence file and check its format using the terminal:

ls -la
file archive.net
Step 2: Decoding Base64 & Identifying Net Data

Notice trailing `=` signs indicating Base64 encoding. Decode it into an IBM Net Data file:

base64 -d archive.net > archive_decoded.bin
file archive_decoded.bin
Step 3: Setting Up a Python Virtual Environment

Create an isolated directory workspace so installed parsing libraries don't mess up your system:

python3 -m venv .venv
source .venv/bin/activate
pip install XMI-reader
Step 4: Extracting the Archive

Run the extraction tool to unpack the mainframe dataset, rename it to a standard `.zip`, and extract contents:

extract-xmi archive_decoded.bin
mv archive_decoded.bin archive.zip
unzip archive.zip
Step 5: Overcoming EBCDIC Encoding

Inspect extracted files in a hex editor (`hexdump`) and spot repeating `40` values (EBCDIC spaces). Convert the database files from EBCDIC to ASCII:

dd if=users of=users.ascii conv=ascii
Step 6: Cracking RACF Password Hashes

Isolate the extracted hashes into a file and run John the Ripper using the RockYou wordlist and best64 rule set:

john --format=racf --wordlist=rockq.txt users.hash

Forensic & Terminal Command Cheat Sheet

Quick reference guide for Linux forensics commands used in the challenge

ls -la File Listing

Lists all files in the current directory in long format, revealing hidden files starting with a dot (`.`).

Example: ls -la /home/user/downloads
file [filename] Type Identification

Analyzes magic bytes inside a file to determine its true format regardless of file extension.

Example: file archive.net
base64 -d Decoding

Decodes Base64 encoded text back into raw binary or readable data streams.

Example: base64 -d encoded.txt -o decoded.bin
python3 -m venv .venv Environment

Creates an isolated Python virtual environment folder named `.venv`.

Example: python3 -m venv .venv
source .venv/bin/activate Activation

Activates the virtual environment so packages install locally within the project.

Example: source .venv/bin/activate
dd if=in of=out Conversion

Low-level data copy and conversion utility used to translate EBCDIC to ASCII.

Example: dd if=users of=users.ascii conv=ascii
john --format=racf Password Cracking

John the Ripper password cracker configured to target mainframe RACF hashes.

Example: john --format=racf --wordlist=rockyou.txt users.hash
unzip [file.zip] Extraction

Extracts compressed files and directories from standard ZIP archives.

Example: unzip archive.zip
