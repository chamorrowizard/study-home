DNS RECON EASY

> Domain Name Auditing with Dig

Query specific DNS resource records (A, MX, NS, TXT, RP) against designated resolvers to discover mail priority, administrator identities, and obfuscated text flags.

// When to Use This Technique

  • Auditing domain zone records during initial OSINT or network recon phases.
  • Targeting specific internal or non-standard resolvers (e.g., @resolver).
  • Extracting system contacts or flag payloads embedded inside DNS TXT or RP records.

// Why This Specific Approach Works

dig sends raw DNS queries directly to the server specified after the @ symbol, bypassing local system caching. Querying record types sequentially reveals hidden infrastructure details without relying on noisy web crawlers.

// Key Commands & Workflow

1. Query IPv4 Address (A) & Mail Servers (MX):
dig @resolver A fortaigan.net +short & dig @resolver MX fortaigan.net
2. Query Responsible Person (RP) & TXT Records for Flags:
dig @resolver RP fortaigan.net && dig @resolver TXT fortaigan.net
GOTCHA: Mail Server Priority is defined by the lowest preference number in MX records (e.g., 10 mail.target.com takes priority over 20 mail2.target.com). In TXT outputs, remove surrounding quotes and escaped backslashes (\") when submitting CTF flags.

PORT SCANNING EASY

> Nmap Stealth & Service Enumeration

Execute targeted TCP and UDP port discovery across custom port ranges while bypassing ICMP blocks using -Pn and identifying software versions with -sV.

// When to Use This Technique

  • Initial host discovery on targets where ping responses (ICMP) are filtered or blocked.
  • Identifying actual banner software names vs. standard port defaults (e.g., HTTP running on non-80 ports).
  • Auditing stateless UDP services like DNS (53), SNMP (161), or NTP (123).

// Why This Specific Approach Works

By default, Nmap only scans the top 1,000 TCP ports and skips unreachable hosts if ping fails. Explicitly passing -Pn treats the target as online, while -p 1-500 restricts scan bounds to minimize detection and speed up response times.

// Key Commands & Workflow

1. Scan Specific TCP Range without Ping Probe:
nmap -Pn -p 1-500 ports.cityinthe.cloud
2. Perform UDP Scan & Service Version Detection:
nmap -Pn -sU -sV -p 1-100 ports.cityinthe.cloud
GOTCHA: Scanning without -sV only reports assigned default service names from /etc/services, not actual running binaries. Note that UDP scans take significantly longer because non-responsive ports are classified as open|filtered due to packet dropping.

SOURCE ANALYSIS EASY

> Git Commit History & Object Forensics

Investigate exposed Git version control repositories to recover deleted files, inspect branch histories (git branch), extract short commit hashes, and uncover redacted secrets using git log and git show.

// When to Use This Technique

  • Analyzing cloned git repositories or exposed web .git directories.
  • Tracking down initial commit hashes, author metadata, or modified commit messages.
  • Retrieving historical flags or API tokens wiped in recent commits.

// Why This Specific Approach Works

Git never permanently deletes historical commits during simple file updates; changes are saved in compressed object trees. Traversing commit parent nodes via git log exposes every delta in repository history.

// Key Commands & Workflow

1. Clone & Inspect Full History Log:
git clone <repo_url> && cd repo && git log --oneline --all
2. Inspect Specific Commit Diff & List Branches:
git branch -a && git show <commit_hash_8_chars>
GOTCHA: CTF questions asking for "short commit hash" usually require only the first 8 characters of the 40-character SHA-1 digest. If web cloning is blocked, convert SSH repository URLs (git@host:user/repo.git) to HTTPS format (https://host/user/repo).

SERVICE PROBING MEDIUM

> Custom Banner Interaction & Netcat Probing

Interact with non-standard socket listeners that spoof or close connections on active Nmap -sV scans. Establish raw TCP streams via nc to issue interactive service commands.

// When to Use This Technique

  • Nmap basic scan reports a port open, but service scan (-sV) reports closed or generates complex fingerprint payloads.
  • Connecting to custom shell-like interfaces or unknown daemons on ports like 8090.
  • Sending manual command strings (help, version, list, get).

// Why This Specific Approach Works

Nmap -sV sends specific probe buffers that aggressive service listeners reject (resetting TCP connection). A raw Netcat (nc) connection completes the 3-way handshake cleanly without sending unexpected automated probe probes.

// Key Commands & Workflow

1. Connect via Netcat & Issue Interactive Commands:
nc nettrack.cityinthe.cloud 8090
2. In-Session Interaction Protocol: 
# After connection appears to hung, type:
help
# Expected response lists: version, list, get, help
version
list
GOTCHA: Netcat connections to silent services often present a completely blank, hung cursor upon connecting. Do NOT press Ctrl+C immediately—type help or hit Enter to trigger prompt responses. Use nmap --reason to diagnose TCP state details.

CLOUD RECON HARD

> AWS Cloud Instance Metadata Service (IMDS) Recon

Query cloud HTTP metadata endpoints (/latest/meta-data/) across non-standard port proxies (e.g., port 1338) to enumerate Availability Zones, IAM Security Roles, EC2 Instance Types, OS release data, and hidden environment flags.

// When to Use This Technique

  • Discovering an HTTP service exposing endpoints returning strings like latest.
  • Performing SSRF or direct proxy reconnaissance on internal host metadata endpoints.
  • Retrieving temporary AWS IAM security credentials (/meta-data/iam/security-credentials/<role>).

// Why This Specific Approach Works

AWS EC2 virtual machines host a local HTTP service at 169.254.169.254 (or mirror proxies). Appending sub-paths acts as a directory traversal through system properties without needing authentication in IMDSv1.

// Key Commands & Workflow

1. Fetch Availability Zone & Instance Type:
curl -s http://metadata.services.cityinthe.cloud:1338/latest/meta-data/placement/availability-zone
2. Enumerate IAM Role & Security Credentials / Flag:
curl -s http://metadata.services.cityinthe.cloud:1338/latest/meta-data/iam/security-credentials/
GOTCHA: Ensure you include trailing slashes when querying directories like /iam/security-credentials/ to view role names rather than getting empty output. Port scanning tools (Nmap) are unnecessary for this challenge and may trigger SOC alerts.
