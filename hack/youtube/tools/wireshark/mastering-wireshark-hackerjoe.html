Wireshark Display Filters Syntax Guide
Filter Syntax What It Does
tcp Shows only TCP protocol packets.
udp Shows only UDP protocol packets.
ip.addr == 192.168.1.1 Filters traffic to or from a specific IP.
tcp.port == 80 Isolates HTTP web traffic on port 80.
dns Filters domain name system query/response packets.

Analyst Methodology

Forensic Investigation & Attacker Objectives

Discover what security analysts look for during live incident response and how attackers probe networks.

1

Baseline Traffic Discovery

Before spotting anomalies, analysts establish normal network behavior. They check the Protocol Hierarchy and Conversation Windows to see standard bandwidth consumption and active endpoints.

> Statistics -> Protocol Hierarchy
2

Isolating Threat Signatures

When an attacker scans ports or a server goes down, analysts look for repeated [SYN] packets followed immediately by [RST] reset responses, indicating closed ports or active firewall blocks.

> Filter: tcp.flags.reset == 1
3

Reassembling Sessions

Using the Follow TCP Stream feature, analysts reconstruct fragmented packets back into readable text (ASCII/Hex) to inspect unauthorized file transfers, credentials, or cleartext communication.

> Right Click -> Follow -> TCP Stream

Defensive Security Operations

Port-Scan Detection & Packet Review

Analyze authorized lab captures to recognize reconnaissance patterns and protect sensitive traffic.

Phase 1: Detection Offline Capture Review

Identify SYN Scan Patterns

In an authorized lab capture, look for one source sending SYN packets to many destination ports, then correlate responses and timestamps. A SYN alone is not proof of malicious activity.

# Review a capture you are authorized to analyze
tshark -r authorized-lab.pcapng -Y 'tcp.flags.syn == 1 && tcp.flags.ack == 0'
# Wireshark display filter
tcp.flags.syn == 1 && tcp.flags.ack == 0
Analyst cues: Repeated connection attempts across many ports, short intervals, and reset responses may indicate scanning; confirm against asset inventory and expected monitoring.
Phase 2: Traffic Protection Metadata & Protocol Review

Review Cleartext Exposure Safely

Use approved sample captures to identify legacy plaintext protocols and assess exposure without collecting or reproducing credentials, cookies, or tokens.

# Inspect HTTP request metadata in an authorized capture
tshark -r authorized-lab.pcapng -Y 'http.request' -T fields -e frame.number -e ip.src -e http.request.method -e http.host
# Wireshark display filter
http.request
Defensive response: Prefer HTTPS, restrict capture access, minimize retained data, and redact sensitive fields before sharing evidence.

Module 01 Lesson

Introduction & Interface Anatomy

Beginner Analogy (ELI5):

Imagine a bustling post office where millions of letters fly past on conveyor belts every second. Wireshark is like a magical clear-plastic envelope inspector that lets you pluck any letter off the belt, open it up, and read both the address on the outside and the love letter or bill tucked inside.

Technical Definition & The 5 Key Panels:

Wireshark is the world's foremost network protocol analyzer. When opened, its graphical user interface displays 5 distinct sections:

  • Toolbar: Quick access controls for starting/stopping captures.
  • Filter Bar: Type display filters to isolate specific traffic.
  • Packet List Pane: Chronological stream of all captured packets.
  • Packet Details Pane: Hierarchical protocol breakdown of a selected packet.
  • Packet Bytes Pane: Raw hexadecimal and ASCII view of packet data.
Module 02 Lesson

Filters & Profiles

Beginner Analogy (ELI5):

A capture filter is like telling the security guard at the door: "Only let people wearing red shirts into the building" (others are turned away permanently). A display filter is like wearing tinted sunglasses inside: everybody is still in the room, but you only choose to look at the blue items.

Technical Definition & Operators:

Display filters utilize powerful logical operators (`and`/`&&`, `or`/`||`, `not`/`!`) to dissect traffic. Colorization rules assign background and text colors based on filters (e.g., highlighting bad TCP segments in red/black) to spot anomalies instantly.

Module 03 Lesson

Network Statistics & IO Graphs

Beginner Analogy (ELI5):

If individual packets are single cars on a highway, statistics and IO graphs are the traffic helicopter reports showing overall rush hour congestion, average speed, and which off-ramp is completely jammed.

Technical Definition:

Wireshark's statistics menu provides File Properties, Protocol Hierarchy distributions, Conversation counters (bandwidth hogs), Endpoint lists, and IO throughput graphs over time.

Module 04 Lesson

TCP & The 3-Way Handshake

Beginner Analogy (ELI5):

Before two people talk on a phone call, they first dial and say: "Hello?" (SYN), the other replies "Hi, I hear you!" (SYN-ACK), and the first responds "Great, let's chat!" (ACK). That polite greeting is the TCP Handshake.

Technical Definition:

TCP is a connection-oriented, reliable protocol. The 3-way handshake establishes sequence numbers and ensures both client and server are ready for reliable data delivery before application payloads transfer.

Module 05 Lesson

UDP, DHCP & DNS Protocols

Beginner Analogy (ELI5):

TCP is like sending a certified, trackable registered letter that requires a signature. UDP is like shouting a message across a crowded room: it's fast, but you don't check if every single person heard every word.

Technical Definition:

UDP is connectionless and lightweight. Protocols like DHCP (dynamic IP assignment on ports 67/68) and DNS (domain name resolution on port 53) rely on UDP for high-speed transactions.

Module 06 Lesson

Troubleshooting & Port Scans

Beginner Analogy (ELI5):

Imagine someone walking down a hotel hallway rattling every single doorknob. Most doors are locked and immediately slam shut (RST packets). That rattling sound is a port scan.

Technical Definition:

When an attacker runs an nmap scan against closed ports, target firewalls or operating systems respond with RST (reset) packets. Analysts monitor these surges to detect reconnaissance activity.

Authorized Security Lab

Packet Evidence & Privacy

Analyze only approved captures

Use packet captures from a lab or an investigation you are authorized to conduct. Treat captures as sensitive evidence: limit access, preserve the original, record provenance, and follow retention and disclosure policies.

Correlate signals, not assumptions

A burst of SYN requests or plaintext HTTP may warrant investigation, but neither proves hostile intent. Correlate timestamps, source and destination endpoints, expected asset behavior, and relevant logs before drawing conclusions.

Minimize exposed data

Avoid opening or sharing payloads containing credentials, cookies, tokens, or personal information unless specifically required by an authorized incident process. Prefer metadata, redact sensitive fields in working copies, and use encrypted protocols such as HTTPS to prevent plaintext exposure.
