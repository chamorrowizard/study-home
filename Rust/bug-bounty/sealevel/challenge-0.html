Missing Signer Authorization

When an Anchor instruction accepts a raw AccountInfo<'info> instead of Signer<'info>, the Solana runtime never verifies that the account's private key signed the transaction—allowing any attacker to impersonate any victim address.

Component Inspector Line 15 • Critical Flaw

Unchecked AccountInfo<'info>

In Anchor, AccountInfo<'info> is a raw wrapper around Solana's underlying account metadata. It performs zero ownership checks, zero data deserialization, and zero signature verification.

⚠ Why An Attacker Can Abuse This

Because ctx.accounts.authority.is_signer is never checked, an attacker simply constructs an AccountMeta::new_readonly(victim_pubkey, false). The Solana runtime sees is_signer = false, doesn't require a cryptographic signature from the victim, and passes the account straight into log_message.
