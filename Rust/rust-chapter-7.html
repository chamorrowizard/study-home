Chapter 7 Overview: Managing Growing Projects

Rust provides a comprehensive module system to manage code scope, privacy, and organization across projects. Master Packages, Crates, Modules, Paths, and file separation to build scalable, encapsulated software.

7.1 Packages and Crates

Cargo & Compilation

A crate is the smallest unit of code the Rust compiler considers at a time (producing a binary or library). A package contains a Cargo.toml file that describes how to build one or more crates. Write a Cargo command to initialize a new binary package.

bash — terminal
Target Prompt
cargo new my_project

7.2 Defining Modules for Scope & Privacy

Modules

Modules organize code within a crate for readability and ease of reuse. Everything in Rust is private by default. Define an inline front_of_house module containing a public sub-module hosting.

src/lib.rs
Target Prompt
mod front_of_house { pub mod hosting {} }

7.3 Referencing Items with Paths

Paths

Paths navigate the module tree. An absolute path starts from the crate root using crate. A relative path starts from the current module using self or super. Call the public function add_to_waitlist() inside hosting using an absolute path.

src/lib.rs
Target Prompt
crate::front_of_house::hosting::add_to_waitlist();

7.4 Bringing Paths into Scope & Re-exporting

use & pub use

The use keyword creates shortcuts to items in scope. Adding pub use re-exports the item, allowing external code to access it as if it were defined directly in that scope. Re-export hosting publicly.

src/lib.rs
Target Prompt
pub use crate::front_of_house::hosting;

7.5 Separating Modules into Different Files

File System

As modules grow, move their definitions into separate files. Declaring mod front_of_house; in src/lib.rs tells Rust to load the module contents from src/front_of_house.rs or src/front_of_house/mod.rs. Declare the external module.

src/lib.rs
Target Prompt
mod front_of_house;

7.6 Crate-Wide Visibility with pub(crate)

Visibility

Sometimes an item needs to be accessible across different modules inside your library, but kept hidden from external consumers. Using pub(crate) restricts visibility strictly to the current crate boundaries.

src/db/connection.rs
Target Prompt
pub(crate) fn connect_internal() {}

7.7 Parent Module Access with pub(super)

Visibility

To make a helper function visible only to its immediate parent module (and sibling sub-modules), use pub(super). This limits exposure while maintaining clean internal encapsulation.

src/auth/crypto/keys.rs
Target Prompt
pub(super) fn validate_key() {}

7.8 Struct Field Visibility & Constructor Patterns

Encapsulation

Making a struct pub does not make its fields public. Private fields force external code to use public constructor methods like new(), upholding invariant rules. Declare a struct with a public field and a private field.

src/models/user.rs
Target Prompt
pub struct User { pub name: String, hashed_pass: String }

7.9 Nested Import Paths & Self References

Imports

To keep import sections readable and satisfy clippy, group items from the same crate using nested paths. Combine importing a module itself alongside its child sub-items using the self keyword.

src/main.rs
Target Prompt
use std::io::{self, Read, Write};

7.10 Ergonomic Library Design: The Prelude Pattern

Architecture

Large Rust libraries (like `tokio` or `serde`) re-export core traits and types inside a prelude module. Consumers can import everything they need for standard library usage with a single wildcard import.

src/lib.rs
Target Prompt
pub use crate::prelude::*;

7.11 Multi-Crate Architecture with Cargo Workspaces

Cargo Workspaces

Large projects split code into multiple co-dependent crates managed under a single root Cargo.toml. Define a workspace containing api and core crates.

Cargo.toml
Target Prompt
[workspace] members = ["crates/api", "crates/core"]

7.12 Resolving Naming Conflicts with the as Keyword

Aliasing

When importing types with identical names from different modules (e.g., std::fmt::Result and std::io::Result), use the as keyword to alias one locally and prevent collisions.

src/main.rs
Target Prompt
use std::fmt::Result as FmtResult;

7.13 Modern Directory Layout (2018+ Edition Rules)

Idiomatic Layout

In modern Rust, avoid cluttering directories with mod.rs files. Instead, create src/auth.rs alongside a matching folder src/auth/ for sub-modules. Declare sub-module tokens inside src/auth.rs.

src/auth.rs
Target Prompt
pub mod tokens;

7.14 Specific Ancestor Visibility with pub(in path)

Advanced Privacy

For granular access control in complex module trees, pub(in crate::path) restricts visibility strictly to a designated ancestor module and its children.

src/network/protocol/secret.rs
Target Prompt
pub(in crate::network) fn handshake() {}

7.15 Third-Party Dependencies & The Glob Operator

External Crates

External crates declared in Cargo.toml are automatically available in your root scope. Import third-party items using absolute crate roots or glob wildcard patterns (commonly used in tests).

tests/integration_test.rs
Target Prompt
use my_crate::*;

7.16 Macro Scoping & #[macro_export]

Macros

Declarative macros (macro_rules!) do not follow standard module visibility rules. To export a macro to the root of the crate (making it accessible externally), decorate it with the #[macro_export] attribute.

src/macros.rs
Target Prompt
#[macro_export] macro_rules! my_log { () => {}; }

7.17 Conditional Module Compilation with #[cfg]

Compilation

You can conditionally compile entire modules based on target OS, architecture, or Cargo features. Use #[cfg(test)] to compile inline unit test modules only when running cargo test.

src/lib.rs
Target Prompt
#[cfg(test)] mod tests { use super::*; }

7.18 Custom File Paths with #[path]

Attributes

By default, Rust looks for module files matching the module name. The #[path] attribute lets you override the default file location and point a module to an arbitrary path.

src/lib.rs
Target Prompt
#[path = "custom/win_os.rs"] mod os;

7.19 Granular Item Re-exporting for Cleaner APIs

API Design

Instead of re-exporting entire sub-modules, you can re-export specific individual items (like structs or traits) to flatten public API hierarchies and hide complex internal folder structures.

src/lib.rs
Target Prompt
pub use crate::internal::engine::Engine;

7.20 Referencing Library Crates in Integration Tests

Integration Tests

Integration tests in the tests/ directory operate as completely separate external crates. They cannot access private items and must import the library using the package name declared in Cargo.toml.

tests/api_test.rs
Target Prompt
use my_project::connect_internal;
