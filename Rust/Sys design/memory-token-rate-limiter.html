Building a Thread-Safe Token Bucket Rate Limiter

Rate limiters sit at the edge of backend systems to prevent API abuse and database overloads. Implementing one in Rust forces you to master thread safety, atomic state sharing, and modular struct design from day one.

use std::collections::HashMap;
use std::sync::{Arc, RwLock};
use std::time::{Duration, Instant};

/// Represents a single user's API rate limit bucket.
struct TokenBucket {
    capacity: usize,
    tokens: usize,
    last_refill: Instant,
    refill_rate: Duration,
}

impl TokenBucket {
    fn new(capacity: usize, refill_rate: Duration) -> Self {
        Self {
            capacity,
            tokens: capacity,
            last_refill: Instant::now(),
            refill_rate,
        }
    }

    fn allow_request(&mut self) -> bool {
        self.refill();
        if self.tokens > 0 {
            self.tokens -= 1;
            true
        } else {
            false
        }
    }

    fn refill(&mut self) {
        let now = Instant::now();
        let elapsed = now.duration_since(self.last_refill);
        let tokens_to_add = (elapsed.as_millis() / self.refill_rate.as_millis()) as usize;

        if tokens_to_add > 0 {
            self.tokens = (self.tokens + tokens_to_add).min(self.capacity);
            self.last_refill = now;
        }
    }

    fn is_stale(&self, ttl: Duration) -> bool {
        self.last_refill.elapsed() > ttl
    }
}

/// Sharded Rate Limiter to eliminate lock bottlenecks and prevent memory leaks.
#[derive(Clone)]
pub struct ProductionRateLimiter {
    shards: Arc>>>,
    shard_count: usize,
    default_capacity: usize,
    refill_rate: Duration,
    ttl: Duration,
}

impl ProductionRateLimiter {
    pub fn new(default_capacity: usize, refill_rate: Duration, ttl: Duration) -> Self {
        const SHARDS: usize = 16;
        let mut shard_vec = Vec::with_capacity(SHARDS);
        for _ in 0..SHARDS {
            shard_vec.push(RwLock::new(HashMap::new()));
        }

        Self {
            shards: Arc::new(shard_vec),
            shard_count: SHARDS,
            default_capacity,
            refill_rate,
            ttl,
        }
    }

    fn get_shard_index(&self, user_id: &str) -> usize {
        use std::hash::{Hash, Hasher};
        let mut hasher = std::collections::hash_map::DefaultHasher::new();
        user_id.hash(&mut hasher);
        (hasher.finish() as usize) % self.shard_count
    }

    pub fn check_user(&self, user_id: &str) -> bool {
        let shard_idx = self.get_shard_index(user_id);

        // Recover safely if lock was poisoned
        let mut shard = self.shards[shard_idx]
            .write()
            .unwrap_or_else(|poisoned| poisoned.into_inner());

        let bucket = shard
            .entry(user_id.to_string())
            .or_insert_with(|| TokenBucket::new(self.default_capacity, self.refill_rate));

        bucket.allow_request()
    }

    /// Removes inactive buckets to prevent RAM leaks
    pub fn cleanup_stale_entries(&self) {
        for shard_lock in self.shards.iter() {
            let mut shard = shard_lock
                .write()
                .unwrap_or_else(|poisoned| poisoned.into_inner());

            shard.retain(|_, bucket| !bucket.is_stale(self.ttl));
        }
    }
}

fn main() {
    let limiter = ProductionRateLimiter::new(3, Duration::from_secs(1), Duration::from_secs(5));
    let user = "user_123";

    for i in 1..=4 {
        println!("Request {}: Allowed? {}", i, limiter.check_user(user));
    }

    limiter.cleanup_stale_entries();
}

Core Concepts You Must Master

1. Lock Sharding

Instead of a single global lock, hashing users across 16 independent RwLock shards eliminates lock contention under high API traffic.

2. Memory Eviction (TTL)

Without cleanup, unbounded maps cause memory leaks. Sweeping stale entries with retain() purges inactive users safely.

3. Poison Resilience

Using unwrap_or_else prevents a single thread panic from ruining the mutex lock and crashing all worker threads.

4. Modular Architecture

Separating bucket math from sync logic allows clean AI-assisted refactoring without risking core state management bugs.

5. Lazy Computation

Token refill is calculated dynamically via timestamp deltas during checks, avoiding background polling threads.

6. Zero-GC Latency

Compile-time scope ownership manages allocations cleanly, keeping API response latency consistent without GC pauses.
