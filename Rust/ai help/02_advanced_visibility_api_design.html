// src/execution.rs
//! Sealed Trait Pattern: Prevents external downstream crates 
//! from implementing `Executable` on their custom types!

mod private {
    // Private trait inside a private module
    pub trait Sealed {}
}

// Public trait requiring `private::Sealed` as a supertrait
pub trait Executable: private::Sealed {
    fn execute(&self) -> Result<(), String>;
}

pub struct SystemTask;

// WE implement the private marker trait for OUR type
impl private::Sealed for SystemTask {}

// Now we can implement the public trait!
impl Executable for SystemTask {
    fn execute(&self) -> Result<(), String> {
        println!("Task executed safely!");
        Ok(())
    }
}
// Downstream consumers can USE `Executable`, but CANNOT implement it for their own structs!
// src/lib.rs
//! Feature-Gated Modules and Structs
//! Reduces compile times & dependency overhead by conditionally including code.

pub mod core_engine;

// Only compiled when the "async-telemetry" Cargo feature is enabled!
#[cfg(feature = "async-telemetry")]
pub mod telemetry;

// Conditionally compile a struct method based on runtime features
pub struct DatabaseDriver;

impl DatabaseDriver {
    pub fn connect() {
        println!("Standard Database Connection");
    }

    #[cfg(feature = "postgres")]
    pub fn connect_postgres_pool() {
        println!("PostgreSQL Pool Initialized");
    }
}
// src/macro_helpers.rs
//! Hidden Public Items
//! Items that MUST be `pub` for procedural macros, but should be hidden from docs.

/// Public function that users should call
pub fn process_order() {
    __internal_macro_guard();
    println!("Order processed.");
}

/// MUST be `pub` so generated macro code in other crates can invocation-link it.
/// BUT hidden from generated HTML documentation (`cargo doc`).
#[doc(hidden)]
pub fn __internal_macro_guard() {
    // Internal state check required by macro expansion
}

Level 2 System Pillars

Sealed Traits

Controls who can implement a public trait. By binding it to a private supertrait, you ensure third-party users cannot break future API stability by adding custom impls.

CS Principle: Non-Extensible Interface Contracts

Conditional Features (#[cfg])

Allows consumers to opt into heavy dependencies (e.g., Tokio, Serde, Postgres) only when needed. Keeps bin targets lightweight and compilation fast.

CS Principle: Dead-Code Elimination & Modular Compiles

Modern Module Hierarchy

Avoids `mod.rs` file clutter. Modern Rust uses `src/account.rs` alongside a sub-folder `src/account/nested.rs` for clean, unambiguous navigation in large codebases.

CS Principle: File System & Namespace Cohesion

Macro Helper Protection

Using #[doc(hidden)] allows internal functions to be marked `pub` for procedural macros without cluttering public API documentation.

CS Principle: Metaprogramming Boundary Control

Production API Evolution Roadmap

STAGE 01

Internal Crate API

Use pub(crate) to allow internal modules to share utilities without exposing them externally.

STAGE 02

Public Sealed API

Expose traits with Sealed patterns so users can invoke methods without introducing uncontrolled trait implementations.

STAGE 03

Feature-Gated Library

Wrap external dependencies inside #[cfg(feature)] to allow consumers to opt into light vs heavy builds.
