Chapter Overview: Making Bad States Unrepresentable

Traditional code heavily relies on runtime checks (e.g., if !conn.is_open { return Err(...) }). In Rust, we can shift these checks from runtime panics to compile-time guarantees. By leveraging Enums, Newtypes, and the Typestate pattern, we eliminate invalid states before the program even runs.

Level 1: Data Modeling with Enums

Enums

Instead of using a struct with optional fields like paid: bool, receipt: Option<Receipt>, and error: Option<String> (which allows invalid states like paid with an error), use an enum. Enums enforce that an entity exists in exactly one valid state at a time.

src/invoice.rs — Define state enum
Target: enum Invoice { Pending, Paid(Receipt), Failed(String) }
>

Level 1.5: Exhaustive Pattern Matching

Match

Rust's match expressions force you to handle every enum variant. If a new state is added in the future, the compiler alerts you immediately everywhere that state isn't handled.

src/invoice.rs — Exhaustive match
Target: match invoice { Invoice::Pending => wait(), Invoice::Paid(r) => store(r), Invoice::Failed(e) => log(e) }
>

Level 2: Domain Modeling with Newtypes

Newtypes

Raw primitive types like f64 for currency or String for emails allow invalid data (e.g., negative amounts, invalid emails, rounding bugs). Wrap primitives in custom tuple structs (Newtypes) that can only be constructed via validated constructors.

src/domain.rs — Define Email wrapper
Target: pub struct Email(String);
>

Level 3: The Typestate Pattern

Typestate

Move dynamic boolean flags (like is_open: bool) into zero-sized state marker types (e.g., Open, Closed). By binding state-specific methods directly to specific generic implementations, invalid actions (like sending data over a closed connection) fail at compile time.

src/connection.rs — Typestate implementation
Target: impl Connection<Open> { pub fn send(&self, msg: String) {} }
>

Level 4: Compile-Time Builder Pattern

Builder

Avoid runtime errors from missing required fields when constructing complex structs. Use phantom generic markers (e.g., Set vs Unset) so required setter methods must be called before .build() becomes available in the type system.

src/builder.rs — Type-safe builder
Target: impl ConfigBuilder<Set, Set> { pub fn build(self) -> Config { Config } }
>

Level 5: Explicit Validation via TryFrom

Traits

Never expose public constructors like Email::new(String) or .from(f64) if raw values could be invalid. Implement TryFrom to parse domain objects safely at input boundaries (APIs, DBs) and force error handling during construction.

src/domain.rs — Fallible conversion
Target: impl TryFrom<String> for Email { type Error = ParseError; }
>

Level 6: Contextual Error Handling

Error Handling

Avoid raw .unwrap() or generic string errors in production. Use thiserror for domain-specific library errors or attach context with anyhow at boundary calls so runtime failures explain why they happened.

src/main.rs — Contextual Result
Target: conn.connect().context("Failed to establish server connection")?
>

Level 7: RAII & Automatic Cleanup

RAII

Never rely on manual cleanup calls like conn.close() which can be forgotten. Implement the Drop trait so state cleanup, file handles, or network sockets are automatically flushed and closed when going out of scope.

src/connection.rs — Drop implementation
Target: impl<S> Drop for Connection<S> { fn drop(&mut self) { self.flush(); } }
>

Level 8: Zero-Allocation Strings

Performance

Avoid unnecessary heap allocations when accepting or returning string data that might not need mutation. Use Cow<'a, str> to borrow string slices by default and only allocate a new String when modification is required.

src/sanitize.rs — Cow String wrapper
Target: pub fn sanitize<'a>(input: &'a str) -> Cow<'a, str> { Cow::Borrowed(input) }
>

Level 9: Extension Traits Pattern

API Design

Extend foreign types or standard library types safely without violating the orphan rule. Define a local trait and implement it for the target type to add clean, chainable domain methods to external structures.

src/ext.rs — Extension trait
Target: pub trait StrExt { fn is_valid_email(&self) -> bool; } impl StrExt for str { fn is_valid_email(&self) -> bool { true } }
>

Level 10: Sealed Traits Pattern

API Security

Prevent downstream crates or external consumers from implementing your public traits. By requiring a private, un-exported supertrait constraint (e.g., private::Sealed), you preserve the ability to safely add trait methods in future updates without breaking external code.

src/lib.rs — Sealed trait declaration
Target: pub trait Config: private::Sealed { fn validate(&self); }
>

Level 11: Zero-Overhead Smart Wrappers

Ergonomics

When creating Newtypes for validated data, implement Deref to transparently expose methods from the underlying inner type. This gives you compile-time type safety at boundary checks without sacrificing ergonomic access to standard inner methods.

src/domain.rs — Deref smart wrapper
Target: impl Deref for Email { type Target = str; fn deref(&self) -> &str { &self.0 } }
>

Level 12: Async Cancellation Safety

Async

Dropping a future at an .await point can leave state partially mutated. Wrap state updates in a atomic transactional guard or hold locks across state transitions so cancellation never causes state corruption.

src/async_state.rs — Cancellation-safe transaction
Target: tokio::select! { res = rx.recv() => handle(res), _ = shutdown.changed() => cleanup(), }
>

Level 13: Non-Exhaustive API Stability

API Stability

When publishing libraries, adding enum variants or struct fields breaks downstream code. Mark public types with #[non_exhaustive] to preserve semver compatibility while allowing future updates.

src/api.rs — Non-exhaustive declaration
Target: #[non_exhaustive] pub enum PaymentStatus { Pending, Completed, }
>

Level 14: Typestate State Transitions

Type System

Consume self by value during typestate state transitions to guarantee that the previous state cannot be reused or accessed after transitioning.

src/state_machine.rs — Consuming transition
Target: impl Connection<Closed> { pub fn connect(self) -> Connection<Open> { Connection { state: PhantomData } } }
>

Level 15: Pinning Unmovable Types

Memory

Use Pin<Box<T>> or tokio::pin! for self-referential structs or futures across .await points to ensure memory locations remain fixed and pointer references stay valid.

src/pinning.rs — Pinning future
Target: let fut = async { process().await }; tokio::pin!(fut); (&mut fut).await;
>

Level 16: Thread-Safe Shared State

Concurrency

Share state safely across concurrent threads or async tasks without race conditions. Use Arc<RwLock<T>> to allow multiple concurrent readers or a single exclusive writer.

src/state.rs — Thread-safe wrapper
Target: pub type SharedState<T> = Arc<RwLock<T>>;
>

Level 17: Explicit Struct Lifetimes

Lifetimes

Store references inside structs without copying or cloning underlying data. Explicitly tie the struct's validity lifetime to the borrowed inner data.

src/borrow.rs — Struct lifetime annotation
Target: pub struct Parser<'a> { input: &'a str, }
>

Level 18: Dynamic Dispatch via Trait Objects

Dispatch

Store diverse types implementing a common trait in a single collection by using dynamic dispatch with heap-allocated trait objects (Box<dyn Trait>).

src/dispatch.rs — Trait object collection
Target: pub type PluginList = Vec<Box<dyn Plugin>>;
>

Level 19: Lock-Free Atomic State

Atomics

For high-performance primitive flags or counters shared across threads, avoid mutex locking overhead. Use atomic types (like AtomicBool) with explicit memory ordering (e.g., Ordering::SeqCst).

src/flag.rs — Lock-free atomic swap
Target: pub fn set_ready(flag: &AtomicBool) { flag.store(true, Ordering::SeqCst); }
>

Level 20: Safe Foreign Function Interfaces

FFI

When passing structs across C binary boundaries or interfacing with system libraries, override Rust's struct layout optimization using #[repr(C)] to guarantee C-compatible memory layout alignment.

src/ffi.rs — C-compatible struct layout
Target: #[repr(C)] pub struct NativePacket { pub id: u32, pub payload_len: u64, }
>
