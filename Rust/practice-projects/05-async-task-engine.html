Async Worker Task Processing Engine

Master Rust's asynchronous ecosystem using tokio and tokio::sync::mpsc. Build job queues, dispatch non-blocking tasks, and handle concurrency without blockages.

Production Implementation

src/main.rs Tokio 1.x Async 
use std::time::Duration;
use tokio::sync::mpsc;
use tokio::time::sleep;

#[derive(Debug)]
pub struct Job {
    pub id: usize,
    pub payload: String,
    pub duration_ms: u64,
}

#[tokio::main]
async fn main() {
    // 1. Create a bounded mpsc channel with a buffer capacity of 32
    let (tx, mut rx) = mpsc::channel::(32);

    // 2. Spawn consumer worker task
    let worker_handle = tokio::spawn(async move {
        println!("[Worker Engine] Ready to process incoming jobs...");
        while let Some(job) = rx.recv().await {
            println!("[Worker Engine] Executing Job #{} ({})", job.id, job.payload);
            sleep(Duration::from_millis(job.duration_ms)).await;
            println!("[Worker Engine] Completed Job #{}", job.id);
        }
        println!("[Worker Engine] Channel closed. Worker shutting down.");
    });

    // 3. Dispatch background tasks concurrently
    for i in 1..=5 {
        let job = Job {
            id: i,
            payload: format!("Task payload data batch_{i}"),
            duration_ms: 300 * (i as u64),
        };

        println!("[Dispatcher] Submitting Job #{}", job.id);
        tx.send(job).await.expect("Failed to send job to queue");
    }

    // Explicitly drop sender handle so worker knows no more messages are coming
    drop(tx);

    // 4. Wait for worker task completion
    worker_handle.await.unwrap();
}

Core Concepts & Mechanics

1. Bounded MPSC Channels

mpsc::channel(capacity) prevents memory bloat by pausing producers when the task queue reaches maximum capacity.

2. Non-blocking Async Recv

rx.recv().await yields execution back to Tokio's runtime whenever the channel is idle, taking 0 CPU cycles while waiting.

3. Task Lifecycle Management

Dropping all Sender instances signals channel closure, allowing consumer loops to exit cleanly.

4. Cooperative Multitasking

Using tokio::time::sleep yields control back to Tokio instead of locking up the OS thread like std::thread::sleep.
