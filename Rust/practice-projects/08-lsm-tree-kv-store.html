LSM-Tree Key-Value Engine

Master write-optimized database storage internals. Build a persistent Key-Value engine featuring Write-Ahead Logging (WAL), in-memory MemTables, and SSTable disk flushes.

Production Implementation

src/main.rs Rust Storage Engine 
use std::collections::BTreeMap;
use std::fs::{File, OpenOptions};
use std::io::{BufRead, BufReader, Write};

pub struct LsmEngine {
    memtable: BTreeMap,
    wal_file: File,
    capacity: usize,
    sstable_count: usize,
}

impl LsmEngine {
    pub fn open(capacity: usize) -> std::io::Result {
        let wal_file = OpenOptions::new()
            .create(true)
            .append(true)
            .read(true)
            .open("engine.wal")?;

        let mut engine = LsmEngine {
            memtable: BTreeMap::new(),
            wal_file,
            capacity,
            sstable_count: 0,
        };

        engine.recover_from_wal()?;
        Ok(engine)
    }

    /// Replay WAL into MemTable on engine boot
    fn recover_from_wal(&mut mut self) -> std::io::Result<()> {
        let file = File::open("engine.wal")?;
        let reader = BufReader::new(file);

        for line in reader.lines() {
            let entry = line?;
            if let Some((key, val)) = entry.split_once(':') {
                self.memtable.insert(key.to_string(), val.to_string());
            }
        }
        Ok(())
    }

    pub fn set(&mut self, key: &str, val: &str) -> std::io::Result<()> {
        // 1. Append entry to WAL for durability
        writeln!(self.wal_file, "{key}:{val}")?;
        self.wal_file.flush()?;

        // 2. Insert into in-memory MemTable
        self.memtable.insert(key.to_string(), val.to_string());

        // 3. Flush to SSTable if capacity threshold exceeded
        if self.memtable.len() >= self.capacity {
            self.flush_sstable()?;
        }

        Ok(())
    }

    pub fn get(&self, key: &str) -> Option {
        // Look in MemTable first (hot path)
        self.memtable.get(key).cloned()
    }

    fn flush_sstable(&mut self) -> std::io::Result<()> {
        self.sstable_count += 1;
        let filename = format!("sstable_{}.db", self.sstable_count);
        let mut sstable = File::create(&filename)?;

        for (k, v) in &self.memtable {
            writeln!(sstable, "{k}={v}")?;
        }

        // Clear MemTable & truncate WAL
        self.memtable.clear();
        self.wal_file = File::create("engine.wal")?;
        println!("[Engine] MemTable flushed to disk: {filename}");
        Ok(())
    }
}

fn main() -> std::io::Result<()> {
    let mut db = LsmEngine::open(3)?;

    db.set("user_101", "Alice")?;
    db.set("user_102", "Bob")?;
    db.set("user_103", "Charlie")?; // Triggers SSTable flush

    if let Some(val) = db.get("user_101") {
        println!("Retrieved user_101: {val}");
    }

    Ok(())
}

Architecture Breakdown

1. Write-Ahead Log (WAL)

Synchronous, append-only disk buffer guaranteeing no committed key-value writes are lost in the event of power loss or engine crashes.

2. MemTable (`BTreeMap`)

In-memory sorted tree structure serving active operations. Keeps data lexicographically ordered to simplify SSTable generation.

3. SSTable Disk Flushes

Converts volatile memory blocks into immutable, sorted disk files via sequential I/O streaming, minimizing random drive head seek operations.

4. Crash Recovery Replay

Sequentially parses lines from `engine.wal` during initial startup to reconstruct the MemTable state up to the last valid transaction.
